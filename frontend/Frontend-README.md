# ICN My Station | 프론트엔드 협업 가이드

**최종 업데이트: 2026-11-04**

인천국제공항 이용객을 위한 실시간 운항 정보 및 분석 대시보드 프로젝트입니다.

- **Frontend:** React + Vite + TypeScript
- **Backend:** FastAPI + Python
- **주요 기능:** 운행현황, 운항통계, 출국장 혼잡도, 날씨 및 운항 여건, 편의시설, 스마트 알림
- **저장소:** `donacana/icn-my-station-db`
- **프론트 개발 브랜치:** `feature/frontend-dashboard`
- **Jenkins 작업 브랜치:** `feature/jenkins-setup`

---

## 1. 프로젝트 진행 상황

현재 메인 대시보드의 기본 레이아웃과 주요 기능별 컴포넌트 개발을 진행하고 있습니다.

| 기능         | 진행 상황 | 주요 내용                          |
| ---------- | ----- | ------------------------------ |
| 메인 대시보드    | 구현 진행 | 티켓형 레이아웃, T1/T2 선택, 기능별 화면 배치  |
| 운행현황       | 구현 진행 | 출발·도착 항공편 타임라인, 편명 및 상태 표시     |
| 운항통계       | 구현 진행 | 운항 현황 요약, 상태별 통계, 시간대별 그래프     |
| 출국장 혼잡도    | 구현 진행 | T1/T2 혼잡도 표시, SVG 기반 히트맵       |
| 날씨 및 운항 여건 | 구현 진행 | 날씨 정보 및 운항 여건 점수 표시, API 연동 작업 |
| 스마트 알림     | 팀원 담당 | 중요 알림 우선순위 및 최신 알림 표시          |
| 편의시설       | 팀원 담당 | 시설 정보 및 여유로운 시설 추천 기능          |

**참고:** 위 상태는 기능 개발이 진행 중임을 의미하며, 모든 기능의 실제 DB 연동과 최종 테스트가 완료되었다는 뜻은 아닙니다.

현재 일부 API는 Mock 데이터로 동작할 수 있습니다. 실제 데이터를 확인하려면 백엔드 실행 환경을 별도로 점검해야 합니다.

## 3. 개발 환경 및 라이브러리 설치

### Frontend

프로젝트 루트에서 다음 명령어를 실행합니다.

```bash
cd frontend
npm install
npm run dev
```

기본 개발 서버 주소:

`http://localhost:5173`

### 사용 라이브러리

| 라이브러리        | 용도                  |
| ------------ | ------------------- |
| React        | 화면 구성 및 상태 관리       |
| TypeScript   | 타입 검사               |
| Vite         | 개발 서버 및 빌드          |
| Recharts     | 운항통계 그래프            |
| Lucide React | UI 아이콘              |
| D3.js        | SVG 기반 혼잡도 시각화      |
| @types/d3    | D3 TypeScript 타입 지원 |

기본 의존성은 `package.json`과 `package-lock.json`으로 관리합니다.

프로젝트를 처음 내려받았다면 **`npm install`만 실행하면 등록된 라이브러리가 설치됩니다.**

### 혼잡도 시각화 라이브러리

출국장 혼잡도 기능은 SVG와 D3.js를 기반으로 개발하고 있습니다.

D3.js가 등록되지 않은 개발 환경에서는 다음 명령어로 설치할 수 있습니다.

```bash
npm install d3
npm install -D @types/d3
```

- **D3.js:** SVG 요소와 혼잡도 데이터를 연결하여 시각화
- **SVG:** 터미널 도면 표시, 별도 설치 불필요
- **Inkscape:** SVG 도면 제작 및 수정에 사용하며 실행 시 설치 불필요

새 라이브러리를 추가한 담당자는 반드시 `package.json`, `package-lock.json`을 함께 커밋합니다.

### Backend

```bash
cd backend
python -m pip install -r requirements.txt
```

백엔드 패키지는 `requirements.txt`를 기준으로 설치합니다.

## 5. 메인 대시보드 구성

메인 화면은 기능별 주요 정보를 한눈에 확인할 수 있도록 구성합니다.

### 터미널 선택

- 제1여객터미널(T1)
- 제2여객터미널(T2)

터미널에 따라 변경되는 데이터와 변경되지 않는 데이터를 구분합니다.

**터미널 기준 데이터**

- 항공편 운행현황
- 출국장 혼잡도
- 편의시설

**공통 데이터**

- 운항통계
- 날씨 및 운항 여건

스마트 알림은 알림 유형과 API 응답을 기준으로 표시합니다.

### 메인 화면 기능

1. **운행현황:** 출발·도착 항공편과 운항 상태
2. **운항통계:** 정상·지연·결항 및 시간대별 통계
3. **출국장 혼잡도:** 터미널별 혼잡도 및 시각화
4. **날씨 및 운항 여건:** 활주로, 바람, 기상 운항 여건 점수
5. **스마트 알림:** 중요 알림 우선, 최신 알림 3건
6. **편의시설:** 가장 여유로운 시설 3곳 추천 목표

편의시설 추천은 실제 혼잡도 데이터가 제공되는 범위에서 구현합니다. 데이터가 부족하면 임의로 순위를 생성하지 않습니다.

## 6. API 연동 안내

### 공통 API 사용

기존 API 호출 함수는 `src/api/client.ts`에서 관리합니다.

```typescript
import {
  getDashboardSummary,
  getFlights,
  getFlight,
  getCongestion,
  getFlightStats,
  getAlerts,
  getWeather,
  getFacilities,
} from './api/client';
```

각 함수의 매개변수와 응답 타입은 최신 코드 및 API 계약 문서를 확인합니다.

주요 API 주소:

```text
/api/v1/dashboard/summary
/api/v1/flights
/api/v1/stats/flights
/api/v1/congestion
/api/v1/weather
/api/v1/alerts
/api/v1/facilities
```

정확한 요청 주소, 쿼리 매개변수, 반환 타입은 `docs/api-contract.md`와 FastAPI Swagger에서 확인합니다.

### 서버 연결

프론트에서 백엔드 주소를 설정할 때 기존 Vite 프록시 또는 환경 변수를 사용합니다.

환경 변수 방식 예시:

```env
VITE_API_BASE_URL=http://127.0.0.1:8000
```

해당 주소는 로컬 개발용 예시입니다. 실제 실행 환경에 따라 변경해야 합니다.

`.env` 파일과 실제 서버 접속 정보는 Git에 올리지 않습니다.

### Mock 데이터와 실제 DB

백엔드 실행 모드에 따라 실제 데이터와 Mock 데이터가 다르게 표시될 수 있습니다.

- `DATA_MODE=mock`: 테스트용 데이터 사용
- `DATA_MODE=db`: DB 기반 데이터 사용

DB 연결 정보는 백엔드 담당자가 별도로 공유합니다.

**프론트에 표시되는 수치가 실제 공항 통계와 다르다면 먼저 백엔드 실행 모드를 확인합니다.**

## 7. 주요 기능별 개발 참고 사항

### 운행현황

- 항공편 번호 및 항공사 정보 표시
- 출발·도착 구분
- 정상·지연·결항 등 운항 상태 구분
- 예정 시간과 변경된 시간 표시
- 선택 터미널 기준 항공편 조회

### 운항통계

- 전체 운항편 수
- 정상·지연·결항 비율
- 시간대별 운항편 수
- 전일 대비 변화량

운항통계는 현재 API 응답을 기준으로 표시하며, 화면에서 임의의 통계 수치를 만들지 않습니다.

### 출국장 혼잡도

- T1/T2 터미널 구분
- 혼잡 단계별 색상 표시
- SVG 도면을 활용한 혼잡도 시각화
- API의 혼잡도 단계(`level`) 활용
- 30분 전 대비 변화량 활용

백엔드에서 사용하는 임시 혼잡 기준:

| 터미널 | 기준값           |
| --- | ------------- |
| T1  | 200명 / 400명   |
| T2  | 800명 / 2,000명 |

위 기준은 임시값으로, 향후 백엔드에서 변경될 수 있습니다. 프론트에서는 가능하면 반환된 `level` 값을 사용합니다.

추가 예정인 `operationStatus` 필드가 `CHECK_REQUIRED`이면 **운영 확인 필요**라고 표시합니다.

필드가 `null`일 수 있으므로 예외 처리가 필요합니다.

### 날씨 및 운항 여건

- 현재 기상 정보
- 바람 방향 및 풍속
- 활주로 정보
- 출발 지연 위험도
- 기상 운항 여건 점수

`operationScore.score`는 실제 항공편의 운항 성공 확률이 아닙니다.

UI에서 확률과 점수를 혼동하지 않도록 주의합니다.

### 스마트 알림

- 최신 알림 최대 3건
- `isImportant=true`인 중요 알림 우선
- 관련 탑승 알림 묶음 표시
- API 응답 기반 표시

### 편의시설

- 시설 이름 및 위치
- 시설 종류
- 운영 정보
- 시설별 혼잡 정보가 확보된 경우 추천

**현재 API가 시설별 혼잡도를 제공하지 않는다면 가장 여유로운 3곳을 정확하게 계산할 수 없습니다.**

백엔드의 데이터 및 추천 기능 제공 여부를 확인한 후 연결합니다.

## 12. 협업 시 주의사항

- API 요청 주소나 응답 필드를 임의로 변경하지 않습니다.
- `src/api/types.ts`는 자동 생성 파일이므로 직접 수정하지 않습니다.
- 공통 CSS 변경은 다른 페이지에 영향을 줄 수 있으므로 확인합니다.
- API 오류 시 응답 코드와 백엔드 실행 상태를 먼저 확인합니다.
